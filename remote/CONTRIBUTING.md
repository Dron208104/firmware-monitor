# Разработка Firmware Monitor

## Ветки

- `main` — стабильное состояние;
- `codex/<задача>` или `feature/<задача>` — функциональная доработка;
- `fix/<задача>` — исправление;
- `release/<версия>` — подготовка релиза.

## Коммиты

Сообщения пишутся по-русски и описывают один логический результат:

```text
Добавить получение версии по SNMPv3
Исправить выравнивание действий оборудования
Подготовить установку версии 1.1.0
```

Не добавляйте в Git `.env`, базы, резервные копии, ключи, журналы и пользовательские загрузки.

## Проверка изменения

```bash
python -m compileall -q app tests
pytest -q
docker compose config --quiet
docker compose build
```

Для интерфейсных изменений проверьте основные страницы в браузере. Для изменения схемы базы проверьте как новую установку, так и обновление копии существующей базы.

## Выпуск

1. Обновить `VERSION`, `APP_VERSION` по умолчанию и `CHANGELOG.md`.
2. Выполнить все тесты и сборку образа.
3. Создать аннотированный тег `vX.Y.Z`.
4. Опубликовать Docker-образ с тегами `X.Y.Z` и `latest` только для стабильного релиза.
5. Проверить обновление и откат на тестовом экземпляре.
